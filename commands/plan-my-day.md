---
description: Adaptive daily planner anchored on your plans. First run builds a versioned plans profile (current_focus list with deadline + context per item, working style, planning guidelines, a generous workday + rest-day typical-day template + variation rules, anti-patterns). Daily runs lay out the day's LIFE structure — calendar, fitness, meals, walk, bed, habit reminders — plus EMPTY work blocks; it no longer assigns tasks (run /plan-my-work after to fill the blocks with tasks from Plane). `focus` subcommand manages the current_focus list; `library` subcommand shows/edits the work and goals reference cards. Supports profile new/commit for plans-profile, work-library, goals-library, monthly-goals, and weekly-goals.
---
Run this with the Bash tool first, then follow the INSTRUCTIONS block in its output:

```bash
bash "${PBRAIN_DEV_DIR:-${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/plugins/marketplaces/pbrain}}/commands/plan-my-day.sh"
```

**Run bash immediately.** With no verb the script smart-dispatches: it runs the **`plan`** path when today has no plan yet, or the **`update`** path when today's plan already exists (force either with `plan` / `update`). The `plan` path injects today's plans profile (the full lens — `current_focus`, `working_style`, `typical_day`, `daily_anchors`, `variation_rules`, `anti_patterns`), fitness sleep data, diet meal times, today's scheduled session, a compact **3-day shape digest** (not the full recent plans), carry-forward, and today's calendar/habits as context, then hands you the planning instructions from `templates/plan-my-day/plan.txt`. The work/goals libraries are NOT loaded for planning — blocks are empty placeholders and the libraries belong to `/plan-my-work`. Follow the INSTRUCTIONS in its output. If the user passed arguments (e.g. `plan`, `update`, `profile show`, `profile new work-library`, `profile commit`, `focus list` / `focus add` / `focus archive`, or `library work show`), append them to the command. The fitness session is the one hard anchor — always place it in the plan. Don't plan beyond today.

**Habit reconcile is delegated.** After the plan is written (and on `update`), the script emits a `HABIT SCAN` block (from the habit module): (A) scan today's vault entries for habit evidence → mark states, and (B) once the plan file exists, time-match today's one-shot reminders to the planned block times via the single deterministic `reminders-realign-plan` batch (PB-88), then `reminders-sync`. Run (B) once, after the plan is written — don't hand-loop `reminders-reschedule` per habit. Follow it silently. Do not hand-write habit-marking or reminder logic here — `/habits` owns it.

**Tasks moved to /plan-my-work (PB-85).** /plan-my-day lays out LIFE anchors + empty work blocks only; it no longer proposes or assigns tasks. The task ledger is a SEPARATE, standalone `## Work tracker` owned by `/plan-my-work` and is NOT tied to these blocks. After it confirms the day, nudge: "run /plan-my-work to fill today's task ledger." If the user runs `plan-my-day task …`, the script emits `PLAN_MY_DAY_TASK_MOVED` — tell them to use `/plan-my-work task add|remove|list` instead. **Work-after-pmw:** if `/plan-my-work` already ran today, the file holds a `## Work tracker` (surfaced as `work_tracker_present: yes`) and possibly no glance — pmd then lays `## Today at a glance` ABOVE that tracker and leaves it verbatim (a bare invocation routes to the `plan` path in that case, since there's no glance to `update`).

Key hard rules:
- Rebuild (`PLAN_MY_DAY_REBUILD`): build the plans profile part by part with the user — confirm/update/drop each current_focus item, ask working-style questions, set planning_guidelines. Never import silently. The plans profile IS the focus: `current_focus` is the heart; the libraries are stable reference cards.
- Wake time comes from today's fitness entry when recorded — confirm it in passing instead of re-asking.
- Backfill the morning yourself from what the user says — gap-free, no overlaps; they correct, you place.
- Show the computed block layout (blocks + breaks around the anchors) before asking what goes in the blocks.
- Today's calendar events + anything the user flags as non-negotiable come FIRST — they're the day's fixed points and drive preponing/postponing the routine (workout, work, meals shift around them).
- When the plans profile carries a `typical_day` template, lay its workday/rest-day skeleton as today's baseline and apply `variation_rules`: keep the meal COUNT, protect meals + fitness, shrink WORK to absorb pressure (work is the flex variable), keep ≥30 min between wake and the first work block, ask non-gym fitness duration including buffer and shift meals to fit — and only *suggest* (never silently drop) skipping fitness when meals run late AND the last few days were already active.
- Committed profiles are final — changes go through `profile new` → edit draft → `profile commit`. The work/goals libraries are living documents (enrich in place). For weekly-goals and monthly-goals, use `profile new weekly-goals` / `profile new monthly-goals`. The versioned goals store files (monthly-goals/weekly-goals) are resolved by a `period` tag via `pbrain_profile_latest_for_period` (not just the latest version). **Standing prefs for /plan-my-day are another living-document exception (PB-37):** a captured COMMAND preference is folded into the plans profile in place (the field it belongs to — e.g. `working_style.other_prefs` — or the top-level `prefs` array as fallback) with NO version mint; `pbrain_emit_prefs` reads that `prefs` array back next run.
- `working_style` keys in the plans profile: `session_length_min`, `break_min`, `break_activities`, `work_hours_per_day`, `focus_hours`, `last_block_end` — these drive the computed work-block layout.
- **Never auto-commit a draft.** After applying any change to a draft, show the user what changed and ask: "Want to lock this in?" (or similar). Only run `profile commit` when the user explicitly says yes / "lock" / "commit" / "save it". If they ask for more edits, keep modifying the same open draft — do NOT mint a new version.
- Work blocks in "Today at a glance" are GENERIC LIFE-SHAPE PLACEHOLDERS ("Block N — focus work") that protect focus time. PB-85: the task ledger is a SEPARATE, standalone "## Work tracker" owned by /plan-my-work — it is not tied to these blocks. /plan-my-day writes no task log and never touches the tracker.
- **AUTO-LIBRARY**: when the user mentions a project or goal not in any library card, offer to register a shortcut card (name + shortcut + context) so future sessions can reference it by name.

## Morning sequence check

Planning the day works best on top of the morning anchors (journal → gratitude). **Don't check these files yourself** — the script computes them and the nudges are wired into the `plan.txt` / `update.txt` INSTRUCTIONS the bash run hands you. Specifically:

- The journal nudge keys off `TODAY'S DAILY JOURNAL` (emitted as `MISSING` when absent).
- The gratitude nudge keys off the precomputed `gratitude_today_exists: yes|no` header (PB-66 — a model-side file check mis-resolves the path/date and fires a false "gratitude not logged" nudge even when today's entry exists).

Both fire ONCE, folded into the same first Step 0 message, never block, and are **suppressed by a standing preference** that silences the journal/gratitude nudge (global or per-command). Just run the bash command below and follow its INSTRUCTIONS — they carry this gating.
