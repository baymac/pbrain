description: Habit tracking. First run interviews you one question at a time to build a versioned habits profile — each habit with its own criteria (daily / N-per-week / N-per-month, build or limit) and a priority. Day-to-day tracking lives in dated markdown files (life/habit-tracking/<date>.md) you tick like a checklist; a SQLite store is synced from them for analysis. Afterward it shows your progress vs each criteria (✅ met / ⏳ not yet / ⚠️ over), top 20 by priority. Habits are auto-marked from your journaling + planning sessions. Once your diet + fitness profiles exist, the scored defaults "Eat clean" (slip ladder over clean vs unclean meals) and "Sleep well" (deviation vs your normal sleep window) are seeded automatically.
argument-hint: (none) | track | list | history --name "X" | scores [--date YYYY-MM-DD] | profile show|new|commit | add … --category <part>
---
Run this with the Bash tool first (substituting any argument for `$ARGUMENTS`), then follow the INSTRUCTIONS block in its output:

```bash
bash "${PBRAIN_DEV_DIR:-${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/plugins/marketplaces/pbrain}}/commands/habits.sh" "$ARGUMENTS"
```

The script prints one of:

- `HABITS_SETUP_PROFILE` — first run, no profile yet. Follow its INSTRUCTIONS: ask ONE question at a time, starting with "suggest from your entries, or specify yourself?", then gather each habit's own criteria and create it with the `add` subcommand (which mints a stable id and writes valid JSON — never hand-edit the file).
- `HABITS_MIGRATION` — one-time staged migration (0008): some habits have no **part** yet. Follow its INSTRUCTIONS: don't show the dashboard or log anything; propose a part for each uncategorized habit (the seven canonical parts — wellness, fitness-activity, bad-habits, looks, cleanliness, work, diet — or a custom slug; ONE per habit), confirm part by part, write each with `edit --id <id> --category <slug>`, then record with `bash lib/migrations.sh record 0008_habits_categorize`. Only fires on the interactive dashboard path, never when another command drives a habits subcommand.
- `HABITS_DASHBOARD` — profile exists. Give a tight read of the rollup (lead with what needs attention — ⚠️ over-cap, ⏳ high-priority not yet met, nice streaks). When habits carry parts, the rollup is grouped under **part** headers (canonical order, then custom, then Uncategorized), priority-sorted within each. Then offer to open today's tracker, mark a habit, add/edit/archive one, or show history. A habit's part is set with `add … --category <part>` / `edit --id <id> --category <part>` (one part per habit; `--category ""` clears it). Use the subcommands shown; never hand-edit the profile JSON or the tracking table directly. Daily build habits can be linked to a per-day Apple Reminder kept in two-way sync (🔔 in the rollup); this is opt-in per habit — only when the user asks, set one up (`reminder --id <id> --link --time HH:MM`, or `--decline`), don't proactively nag. The dashboard output also carries a HABIT EXTRACTION block: if the user has evidenced any tracked habit in this session (this turn or a later one — e.g. "I had one unclean meal"), MARK it per that block instead of waiting to be asked, so progress updates in the same run. Marking is idempotent, so it's safe.
- `HABITS_TRACK_FILE` — today's dated tracking markdown was created/refreshed; tell the user where it is and that they can tick the Done column (or you'll mark cells as they mention habits).
- **Limit habits record time-of-day + thoughts (PB-138).** When you mark a **limit** habit (`at_most`), capture the clock time(s) it happened into the row's **Times** column and fold the user's reflection into that row's **Note** — both happen automatically for every limit habit, no profile flag. If the user states a time ("snacked around 10pm"), pass it with `mark … --time "22:00"` (comma-separate multiple: `--time "14:30,21:15"`); if they don't, the log moment's clock time is inferred. Build habits ignore `--time` (their Times cell stays blank).
- `HABITS_LIST` — just relay the configured habits.
- `HISTORY: …` — relay the event history for that habit.
- `HABITS_PROFILE_SHOW` / `HABITS_PROFILE_NEW` / `HABITS_PROFILE_COMMITTED` — the versioned-profile subcommand (`profile show|new|commit`). The profile lives in the store at `life/habit-tracking/.profile/habits-profile.vN.md`; day-to-day `add`/`edit`/`archive` keep amending the latest version in place (living document) — `profile new` mints a draft only for structural redesigns, `profile commit` freezes it. **Never auto-commit a draft:** after any change to a draft, show what changed and ask "Want to lock this in?" — only run `profile commit` on explicit yes / "lock" / "commit". More edits → keep modifying the same open draft, do NOT mint a new version. If a draft is already open at session start, continue editing it. **Standing prefs for /habits live in this profile (PB-37):** a captured COMMAND preference is folded into the field it belongs to, or the profile's top-level `prefs` array when nothing fits — edited in place with NO version mint (`pbrain_emit_prefs` reads that `prefs` array back next run; a flat `.pbrain/habits/prefs.md` is only the fallback when no profile exists).

Tracking model: the dated `life/habit-tracking/<date>.md` files are the human-facing log; the SQLite DB is synced from them (read commands sync first; `/end-of-day` consolidates). Mark habits with `mark` (ticks the md), not `log`. Don't pad. This is a dashboard, not a coaching session.

Scored habits: never pick the score yourself — pass raw inputs and the profile rule computes a 0.0–1.0 UNIT value (every scored habit shares this scale; only the model differs). The model only classifies; `score_from_spec` in `lib/habits.sh` — the canonical reference — does the math. The scoring types and how to feed them:

- `slip_ladder` (Eat clean) — slips → ladder index (rungs are 0–1, e.g. `[1, 0.6, 0.3, 0]`); slips = `--bad` + `max(0, good_target − --good)`, so unclean meals AND a shortfall under the clean-meal target both push you down the ladder; `mark --name "Eat clean" --good <clean meals> --bad <unclean meals>`.
- `meal_ratio` — a ratio-style alternative (score = good/(good+bad), so it scales with how many units the day had). NOT what Eat clean uses (Eat clean is `slip_ladder` above); available for habits that want a pure ratio.
- `deviation` (Sleep well) — slips from the circular bed-time diff vs `normal_time` (per `unit_minutes`) + hours shortfall vs `normal_hours` (per `unit_hours`), ladder-indexed (rungs 0–1); `mark --name "Sleep well" --actual-time HH:MM --actual-hours N.N` (bed time + slept hours; normal window from the fitness profile).
- `weighted_completion` (Work the plan) — score = earned/possible (0–1); per-task weight = `difficulty_weights[difficulty]` (easy1/normal2/hard3/nightmare5) × priority boost (`1 + max(0, priority_pivot−priority)·priority_step`, pivot 3 step 0.25); credit = `status_credit[status]` (done1/partial0.5/dropped,carried0); every planned task is in the denominator (overplanning costs you); pass `--items '[{"priority":1,"difficulty":"hard","status":"done"},…]'`.
- `session_volume` (Train) — skipped→0; strength/duration with planned>0 & actual present → clamp(actual/planned,0,volume_cap) (cap 1.0); else binary status_credit[status] (completed1/partial0.5); pass `--session '{"mode":"strength|duration|binary","status":…,"planned":N,"actual":N}'`.
- `focus_ratio` (Deep work) — score = work/(work+distraction) of *active* minutes (0–1); `work_categories`/`distraction_categories` default `["work"]`/`["social","entertainment"]`; `neutral`+`afk` excluded; w+d=0 → unmarked; pass `--focus '{"work":120,"social":30,…}'`.
- `checklist` — fixed daily set of named weighted `components`; score = sum(done weights)/sum(all weights) (0–1); pass parts done by name or id as `--done '[…]'`.

**Default scored habits** are auto-seeded, but **each only when its owning command is enabled** — i.e. that command's committed profile exists (the laptop tracker DB for Deep work). The gates are independent and hard-coded: `/diet-journal` → Eat clean · `/fitness-journal` → Sleep well + Train (+ one per-activity habit per library activity) · `/plan-my-day` → Work the plan · `/laptop-tracking` (+ plans profile) → Deep work. A command the user never set up seeds none of its habits (PB-39 — no Train without `/fitness-journal`); seeding is idempotent and an archived default is never resurrected. They are **weekly aggregates**: scored *daily* (a 0–1 unit score each day, marked at `/end-of-day` — the Count cell holds that day's score), banked over the week as a running **sum out of 7** (Progress `"4/7 wk"`, like Eat clean), with `measure_target` the weekly **pass bar** (`5`, so Criteria reads `weekly ≥5`). The denominator is always the 7-day max; the score never needs a perfect week. They carry **no `notes`** — the script (`score_from_spec`) owns the math and this spec owns the model-facing classification, so nothing duplicates the scale (which is how the prose drifted out of sync). When marking them, classify the raw inputs by these rules, then pass the flag above — never pick the score:
- **Eat clean** (`slip_ladder`, eod) — over the meals ACTUALLY EATEN (never planned), from the diet log. `--good` = clean **main** meals only (breakfast/lunch/dinner, home-cooked / whole-food, cap 3). `--bad` = ANY unclean meal **or** snack at any time (restaurant / takeout / ultra-processed, e.g. Maggi, fries) — a slip even if it looks healthy. Clean snacks don't add to `--good`; junk snacks do add to `--bad`.
- **Sleep well** (`deviation`, eod, today only) — last night's bed time → `--actual-time HH:MM`, hours slept → `--actual-hours N.N`. Normal window comes from the fitness profile.
- **Work the plan** (`weighted_completion`, eod) — one row per **planned** task from the day's task log: `{priority, difficulty, status}` (status `done`/`partial`/`dropped`/`carried`). Every planned task is in the denominator.
- **Train** (`session_volume`, eod) — counts **any** fitness activity (mark it on the days you train; ~6/week). From the LOGGED session, not a planned one. Volume = Σ weight×reps across sets: parse "## Log your sets here" for `actual`, "## Workout" (Sets×Reps + Weight) for `planned`.
- **Deep work** (`focus_ratio`, eod, auto) — from the laptop tracker over the day's WORK-block windows only (meals/gym/walk excluded); per-category minutes via `--focus`. See `/end-of-day`'s deep-work marking sequence.

User-**defined** scored habits are the opposite: the script can't know a custom classification, so put that logic in the habit's `notes` (added via `add … --notes "…"`). The model reads those notes, passes the raw values to `mark`, and the rule computes + saves the score — keep custom notes about *classification*, not the points total. (Such habits can be **daily** too — e.g. a `checklist` habit scored `score/1 day` against a `<1` threshold — not only weekly aggregates.)

When a seeding line ("Added default habit: …") appears in the output, mention it to the user in one line.

Habit↔reminder linking: per-day ONE-SHOT reminder on the days the schedule is due (not Apple-recurring); the link is an intent on the habit (`"reminder":{"state":"linked","time":"HH:MM"}`), while the per-day reminder ids live in the DB table `habit_reminders(habit_id,occurred_on,reminder_id,status)` (idempotency PK). Two-way sync runs via `reminders-ensure` / `reminders-sync [--sweep]`. `reminders-reschedule --habit <name> --time HH:MM [--date]` moves a pending one-shot's due time (used by `/plan-my-day` to align it with the planned block); it returns one of `RESCHEDULED | NOT_LINKED | NOT_FOUND | UNAVAILABLE`. `reminders-realign-plan [--plan <file>] [--date]` (PB-88) is the deterministic batch `/plan-my-day` runs AT THE END of a run, once the plan file exists: it parses the plan's `## Today at a glance` table, matches every LINKED habit by name to its earliest timed row, and `ensure`s+`reschedule`s each one-shot to that row's start time (the ensure-first is why it no longer silently `NOT_FOUND`s when the day was re-timed). Prints `REALIGNED <n> SKIPPED <n>`; the caller runs `reminders-sync` after to push state.
