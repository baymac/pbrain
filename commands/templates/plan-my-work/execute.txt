PER-TASK LIFECYCLE (loop over the current block's not-done rows, top to bottom):

       stop and say so — do NOT create or guess a repo.

  2. [GATE] MARK IN-PROGRESS. On the user's go:
       bash "${PM_CMD}" move "<tie>" --to doing

  3. ISOLATE. Branch off a FRESH base — never a stale HEAD:
       git -C <path> fetch origin

  4. PLAN — SPEC/APPROVAL GATE. Read the issue's recorded plan + approval state

       bash "${PM_CMD}" spec "<tie>" --read
     The PM_SPEC JSON carries `approved`, `has_plan`, `description` (which holds
     the ## Implementation Plan when one exists), and `comments` (the user's
     comments on the issue, oldest→newest, with `comments_authoritative: true`).
     - COMMENTS ARE AUTHORITATIVE (PB-61). The `comments` array OVERRIDES the
       description AND any plan content the model added — on BOTH paths below.
       Read every comment; the LAST (newest) wins where comments disagree. Build

       said Y — going with the comment"), so the stale description gets noticed.
       Empty `comments` → nothing changes; proceed with the description as before.
     - approved = true → FAST PATH. The approach was reviewed ahead of time. Read
       the ## Implementation Plan out of `description` and implement straight

       Then OFFER once, without blocking: "want me to save this as the approved

     Then clean up the worktree (git -C <path> worktree remove <wt>).
